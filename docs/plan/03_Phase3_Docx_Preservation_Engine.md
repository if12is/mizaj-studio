# Phase 3: محرك استيراد وتصدير ملفات Word المتقدم (Non-Destructive DOCX Engine)

**الهدف:** قراءة وتشكيل وتصدير ملفات `.docx` المعقدة مع الحفاظ التام بنسبة 100% على التنسيقات، الجداول، الحواشي السفلية والعلوية، مربعات النصوص، والنصوص المختلطة (عربي/إنجليزي).

---

## Slice 3.1: محلل شجرة XML الشامل ودمج المقاطع (Deep XML & Style-Signature Parser)
**الهدف:** معالجة كافة عناصر ملف الوورد دون فقدان أي تنسيق أو كسر للكلمات العربية.

### المهام (Tasks):
- [x] **Task 3.1.1:** _(ملاحظة: البصمة تُستخدم لعرض منطقي فقط؛ لا يتم دمج الـ runs فعلياً في XML — الحركات تُعاد لكل `w:t` حسب ملكية الحرف الأساسي للحفاظ على التنسيق 100%)_ بناء دالة بصمة التنسيق الدقيقة (**`RunStyleSignature`**) التي تقارن الخصائص السبع التالية قبل دمج أي مقطعين (`Runs`) متجاورين لمعالجة مشكلة انقسام الكلمة العربية في XML:
  `Signature = (run.bold, run.italic, run.underline, run.font.color.rgb if run.font.color else None, run.font.name, run.font.size, run.font.rtl)`
  لا يتم دمج مقطعين متجاورين إلا إذا تطابقت هذه البصمة السباعية بنسبة 100%.
- [x] **Task 3.1.2:** استخراج ومعالجة النصوص من الهيكل الأساسي (`doc.paragraphs`)، **الجداول (`doc.tables` شاملة الخلايا المدمجة والجداول المتداخلة)**، و**الترويسات والتذييلات (`section.header`, `section.footer`, `first_page_header`)**.
- [x] **Task 3.1.3:** دعم **الحواشي السفلية (`w:footnotes`)، التعليقات الختامية (`w:endnotes`)، مربعات النصوص (`w:txbxContent`)، وعناصر التحكم بالمحتوى (`w:sdtContent` / Content Controls)** عبر الوصول المباشر لشجرة `lxml` داخل أرشيف `python-docx` (`doc.part.rels` و `element.xpath`)، مع ترك التعليقات الجانبية للمراجعين (`w:comments`) بدون تغيير إلا إذا طلب المستخدم تشكيلها.
- [x] **Task 3.1.4:** معالجة **النصوص المختلطة (Mixed Arabic/English/Numbers/Code)** داخل نفس الـ `Run` (مثال: `"اشتريت جهاز iPhone 16 Pro الجديد"`):
  * يقوم المحلل بتقسيم النص داخلياً عبر Regex إلى رموز عربية (`[؀-ۿ]+`) ورموز غير عربية (إنجليزي، أرقام، روابط، علامات ترقيم).
  * يتم إرسال الجملة للسياق، وتُحقن الحركات **فقط** على الكلمات العربية (`"اِشْتَرَيْتُ جِهَازَ iPhone 16 Pro الْجَدِيدَ"`) مع بقاء الكلمات الإنجليزية والأرقام في مواضعها الدقيقة دون أي مساس بها.
  * المقاطع المكتوبة بخطوط برمجية (`Courier New`, `Consolas`, `Fira Code`) يتم تخطيها تلقائياً بالكامل.

## Slice 3.2: التشكيل الدفعي، التصدير الذري الآمن، والاختبار بملفات حقيقية (Atomic DOCX Export)
**الهدف:** حقن التشكيل بـ 3 مستويات وتصدير الملف بأمان ضد أخطاء القفل أو امتلاء القرص.

### المهام (Tasks):
- [x] **Task 3.2.1:** تطبيق مستويات التشكيل الثلاثة عند التصدير:
  1. `full`: تشكيل كامل لكافة الحروف.
  2. `irab_only`: إبقاء حركة الحرف الأخير فقط (وعلامة التنوين/الشدة المرتبطة به) لحسم الإعراب.
  3. `minimal`: تشكيل الكلمات التي تملك أكثر من وجه شائع في `mishkal` فقط لمنع اللبس.
- [x] **Task 3.2.2:** تطبيق **الحفظ الذري الآمن (Atomic Save & Lock Protection)**: الكتابة أولاً في ملف مؤقت بجوار الملف الهدف ثم استبداله، وإرجاع الخطأ الموحد `ERR_DOCX_WRITE_LOCKED` (`423`) إذا كان الملف مفتوحاً في برنامج Microsoft Word.
- [x] **Task 3.2.3:** كتابة اختبارات شاملة في `backend/tests/test_phase3_docx.py` تستخدم ملفات الاختبار المرفقة في المستودع (`tests/fixtures/sample_ar.docx` و `tests/fixtures/sample_mixed.docx`) للتحقق من بقاء الجداول والترويسات والكلمات الإنجليزية سليمة 100%.
